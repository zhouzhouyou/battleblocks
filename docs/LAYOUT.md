# 工程目录与资源入库约定

本文件是目录职责、资源入库与特殊目录用途的权威说明。修改文件前必须遵从；目录调整时同步更新本文件、README、AGENTS 和检查规则。

## 游戏资源

`assets/` 只存放当前应该进入游戏的资源，按以下五类组织；不单独设觉醒目录。

```text
assets/
├── roles/<角色>/runtime/  普通、觉醒与独立装备的游戏图集
├── effects/              游戏特效图集
├── environment/          已接入游戏的场景与棋盘资源（目前预留）
├── ui/                   方块、界面、角色缩略图
└── audio/runtime/        游戏音乐与音效
```

普通和觉醒归属同一角色。共享配置、技能、身份、文案、本地化与资源元数据放在 `config/`。游戏代码通过明确的资源路径加载；打包工具不能复制整个制作源目录或图鉴目录。所有发布 WebP 遵从 [无损压缩流程](art/WEBP-EXPORT.md)，构建与打包均检查压缩强度及像素一致性。

## 正式制作源

`assets-source/` 保存当前正式资源的关键制作输入，以及对后续开发有明确参考价值的正式定稿。这些内容不进入游戏包。

```text
assets-source/
├── roles/<角色>/
│   ├── design/        当前采用的人设图
│   ├── animation/     动画源图、帧元数据、配准与调色板
│   ├── equipment/     独立装备制作输入（按需要设置）
│   └── gallery/       已明确保留的图鉴资源制作输入（按需要设置）
├── effects/<特效>/     正式特效制作程序与参数
├── environment/       暂未接入的背景制作输入
└── audio/             音频母版
```

当前方块图片和消除音效直接引用 `assets/ui/` 与 `assets/audio/runtime/crush.wav`；实验音乐引用 `assets/audio/runtime/bgm.ogg`。不为相同内容另存制作源或实验副本；只有存在实质差异的可编辑源才进入 `assets-source/`。

此目录不接收一般候选、讨论稿、早期画风比较、用户引用参考原图或检查输出。图片采用无损 WebP；保留动画帧序、时长、调色板和配准数据，确保制作工具可复现当前资源。传送方块的 `animation/atlas.webp` 是实际重排打包输入，按生产用途保留。

## 特殊目录

| 目录 | 职责与边界 |
| --- | --- |
| `gallery/` | 未来图鉴资源。目前图鉴尚未实现，不加载、不随游戏发布；当前保存明确为图鉴保留的修女立绘。一般讨论稿不能以图鉴名义入库 |
| `src/` | 游戏代码，遵守现有模型与表现分层 |
| `docs/` | 持续有效的架构、工具使用、制作规范与当前设计依据；禁止历史需求、阶段计划、变更提案、重复规则和单次记录 |
| `tools/` | 可复用的制作、构建、分析和检查工具 |
| `experiments/` | 可复现的独立实验代码、说明与必要输入，不随游戏发布 |
| `analysis/` | 兼容旧工具的本地输出目录，整目录忽略；新输出统一放 `.local/` |
| `licenses/` | 授权与第三方来源 |
| `.local/` | 本地候选、用户参考原图、预览、拼图、截图、录屏及新增运行输出，禁止入库 |
| `target/`、`dist/`、`logs/`、`.build-tools/` | 编译、发布、日志与本机缓存，禁止入库 |

图鉴功能正式接入时，将实际需要的运行文件迁入 `assets/`，并更新资源注册与打包清单。实验的新输出放 `.local/` 或已忽略的实验结果目录，不能混入实验源码。

## 入库与历史边界

- 当前树只保留最新正式资源与关键制作输入；被替代的正式资源从当前树移除，允许留在曾正式使用它们的 Git 提交中。未采用讨论稿、preview、contact sheet、比较图和录屏不得进入当前树或提交历史。
- 文字讨论允许入库，包括用户原话及未采纳的人设方向；所有引用的参考原图均不入库，只保留文字说明。正式人设图是本项目制作成果，与用户提供的参考原图有区别。
- 前期画风讨论稿及其文档引用不保留；唯一全局美术规范见 [高细节像素画规范](art/ART-DIRECTION.md)。
- 路径、资源名与文档不附加迭代版本号，不堆叠历史副本。提交记录表达修改过程。
- 所有允许跟踪的二进制及 SHA-256 列入 `config/asset-manifest.json`。确认采用新资源后才更新清单；提交与构建前运行 `python3 tools/check_repository.py`。
- README 必须链接本文件，AGENTS 必须要求遵从本文件。新增特殊目录必须先在此说明用途、入库与发布边界。

## 文档的持续价值

文档用于维护当前系统，不作为研发过程的档案库。只保留持续使用的架构、操作手册、制作规范与当前权威设计；不保存历史需求、阶段计划、OpenSpec 式变更提案、已完成任务清单或重复说明。相同主题只保留一个维护入口。构建、打包、部署与验证选择统一维护在 `BUILDING.md`；平衡评估的唯一说明为 `BALANCE-EVALUATION.md`，由 AGENTS 链接。

角色档案保留当前权威设定及必要的用户原话，不能把旧提案或过时参数写成现行规则。引用的原始参考图仍禁止入库，只保留对当前设计有意义的文字说明。

## 生成产物与单次记录禁止入库

以下内容只能写入 `.local/`、临时目录或其他明确忽略的输出目录；当前树与提交历史都不保留：

- 战斗、调试、回放、编译、测试和录制日志，包括完整状态快照。
- 检测、测量、性能采样、逐帧像素比较、验收证据、原始统计及运行结果；不因采用 JSON、CSV、文本或 Markdown 格式而允许入库。
- 工具标准输出、自动报告、截图、录屏、预览、拼图、缓存与包体测量结果。
- 清洗记录、单次验收、一次性排查和不承担长期规则或复现输入职责的工作记录；不得转存到 `docs/` 绕过规则。

只保留复现所需的代码、配置、确定性测试输入、锁定依赖与关键制作源。日志和检查结果可由这些输入重新产生，不是测试输入。需要长期保留的设计结论应提炼为当前规则或设计依据，不保留单次执行过程。

帧序、时长、配准、调色板、音符表属于制作或程序输入；像素误差数组、采样时间线、成功/失败记录和运行指纹属于输出。结构化输入必须在 `config/repository-inputs.json` 中逐项声明用途。新增 JSON 等数据文件必须通过入库检查，不能把生成报告改名为配置后提交。

检查工具同时覆盖当前索引与全部历史快照。忽略规则无法自动移除已跟踪文件，因此禁止产物还必须从历史过滤。

当前资源按当前 `config/asset-manifest.json` 验证。历史中的每一份资源必须能找到一个可达提交，证明同一路径下的实际文件与该提交的正式清单在 SHA-256 和文件大小上完全一致；允许清单在后续提交中补齐或校正，但仅有清单条目、没有对应实际文件不能作为批准依据。这样既允许曾正式使用的旧资源留在历史中，也兼容历史资源优化后清单才校正的情况，不要求旧资源仍存在于当前树。结构化输入按所在提交的 `config/repository-inputs.json` 验证。早于清单首次建立的祖先提交，资源仍需上述正式批准依据，结构化输入使用首次建立的输入清单核验；清单建立后缺失清单的提交不允许回退。候选图、日志、报告等禁止产物即使列入清单，也不能通过历史检查。正常替换正式资源无需改写 main 历史。

## 提交检查

本地执行 `git config --local core.hooksPath .githooks` 启用仓库提交钩子；新克隆也需要启用。钩子运行 `python3 tools/check_repository.py --staged`，检查真正准备提交的内容，不能用工作树中未暂存的修正掩盖违规文件。

GitHub 的 `Repository policy` 工作流在 push 和 PR 上获取完整历史，检查目录、结构化输入、资源清单和历史中的禁止产物。`main` 上的后续提交须遵从本文件并通过检查。工作流记录由 GitHub 保存，禁止复制进仓库。

## 历史治理

禁止入库的内容也不得留在可达提交历史中。处理已跟踪的生成产物时，忽略规则与历史移除必须同时完成；历史改写在隔离副本中验证，按明确的发布范围同步。执行记录、备份与体积审计结果保存在仓库外，不写入 docs。
