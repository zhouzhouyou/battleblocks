# 被动与平衡模型（2026-10-23）

这是每个角色一个核心机制的首版。最初草案中的引线、钱袋、追猎、架盾和再生尚未加入，避免多个机制同时变化而无法解释平衡结果。

## 当前规则

| 角色 | 被动 | 生命 / 魔力上限 |
| --- | --- | --- |
| 骑士 | 左右交换相邻两整列，上下仍交换两格；消除收益增加6% | 700 / 300 |
| 精灵 | 可以交换斜向相邻两格；仍只认横向、纵向三消；消除收益降低7% | 600 / 500 |
| 巫师 | 每轮消除治疗量的一半（向下取整）等量转为魔力，技能直接治疗不变 | 550 / 800 |
| 哥布林 | 消除的溢出治疗，每2点转为1点魔力，仍受魔力上限限制 | 725 / 500 |
| 小恶魔 | 有收益消除中，每个平衡方块额外提供2伤害、2魔力 | 700 / 500 |
| 角魔 | 每轮消除前，生命不高于35%时，该轮消除伤害增加25% | 600 / 700 |
| 大僵尸 | 魔力不足时，每缺1魔力支付2生命；先扣费，必须至少剩1生命，再结算技能治疗 | 775 / 400 |

消除包括普通交换、转化产生的三消、技能有收益清除及后续连锁。直接技能效果不乘消除被动。先汇总方块值，再乘连锁及增幅，之后执行角色转换或倍率，最后应用生命、魔力上限；各步使用整数向下取整。小恶魔的每格额外值加入基础值后一起乘连锁。角魔判断的是治疗前生命。哥布林只有实际溢出的治疗参与回收。

交换必须形成三消才有效；无效操作不改变棋盘、回合或资源。骑士的同一列对只算一个AI候选，不会因点击了不同的行而重复采样。无路可走检查使用当前行动方自己的交换规则和可用技能，AI和玩家规则相同。

选角页直接显示被动；战斗双方侧栏可悬停查看。选择交换起点后，悬停终点可以预览首轮匹配，骑士同时提示两整列范围；交换动画也移动整列。

## 生命代付提示

- 技能按钮和详情显示红色的实际魔力、生命消耗，即使生命不足也展示所需数量。
- 生命不足时提示“支付后须剩1点”；不能用技能即将获得的治疗抵扣预付生命。
- 点击技能或快捷键先进入目标预览，点击棋盘才释放；Esc、右键或再次按同一快捷键取消。伤害转生在代付生命时也需要这一步确认。
- 详情分别显示净生命变化、扣费后的生命、直接效果及确定性首轮结算后的生命和魔力；随机补充产生的连锁不计入。
- 未确认不扣费。释放后显示“血肉施法”反馈及实际生命变化；JSONL记录 `cost`（实际魔力消耗）、`blood_cost`、`actual_heal`（净生命变化）。回滚直接恢复施法前快照和随机流。

## 可执行模型

`board::hero_swap / hero_options`、`content::clear_rewards / payment / preview_rewards`供游戏、AI和无界面对战工具共用。AI根据当前缺血和魔力剩余空间估计有效收益，代付生命以净生命变化进入技能评分；选择技能目标也使用同一份预览。

标准AI的即时评分为：伤害 + 有效治疗×0.8 + 有效魔力×0.65。技能评分使用伤害 + 净生命变化×0.8 + 魔力净变化×0.5，并保留少量清盘估值。进阶AI在交换时扣除未消除区域给对方留下的最佳机会估值，不预知随机补充。这里的系数是策略假设，不是生命与魔力的固定兑换率。

运行方式：

```sh
cargo run --release --bin balance_probe -- 120 120000 1
```

三个参数分别为每组种子数量、起始种子、AI策略（0随机、1标准、2进阶）。七角色共21个配对，每个种子互换先手，120个种子为5,040局。输出包括角色胜率、配对胜场矩阵、回合上限平局数、行动数中位数、单次爆发90分位、先手胜率，以及各角色交换/施法次数、生命代付次数和总量、有效伤害/治疗/魔力与魔力浪费。

每局上限240次行动，准备技能也计入行动数；同一次清除的连锁限64轮。统计不是真人胜率，也不包含全局最优搜索、技能后随机连锁的精确估值或对手完整的未来规划。

## 调参与独立验证

无被动基线保存在 `analysis/passives-baseline.csv`。第一轮未补偿的被动使精灵达到73.5%、骑士降到37.4%，证明操作空间变化不能只凭直觉定价。中间试验和验证保留在 `analysis/passives-initial.csv`、`passives-tuning*.csv`、`passives-validation*.csv`；它们并非最终版本数据。

最后一次调参使用种子60000–60047；冻结参数后，标准AI使用120000–120119，进阶使用130000–130047，随机使用140000–140047：

| 角色 | 标准（每角色1,440局） | 进阶（每角色576局） | 随机（每角色576局） |
| --- | ---: | ---: | ---: |
| 骑士 | 50.5% | 45.0% | 85.9% |
| 精灵 | 47.4% | 45.3% | 25.2% |
| 巫师 | 53.1% | 57.1% | 29.0% |
| 哥布林 | 48.8% | 50.9% | 48.4% |
| 小恶魔 | 54.2% | 53.0% | 64.8% |
| 角魔 | 47.8% | 47.7% | 59.4% |
| 大僵尸 | 48.1% | 51.0% | 31.9% |

标准样本无平局，中位35次行动，爆发90分位220，先手胜率55.2%。原始最终数据为 `analysis/passives-final-standard.csv`、`passives-final-advanced.csv`、`passives-final-random.csv`。

仍然存在明确问题：标准AI小恶魔对巫师197/240胜（82.1%）；进阶巫师整体57.1%；随机策略严重偏向骑士，且有31局达到行动上限。随机结果说明角色对决策能力的要求差异很大，不能用标准AI的47.4%–54.2%宣称所有策略下都平衡。后续应针对配对克制和真人操作验证，而不是只继续压缩整体胜率。每角色1,440局时，接近50%的胜率其粗略95%抽样区间约±2.6个百分点，固定AI和共享种子还会引入相关性。

## 死局判定修正

2026-10-23 修正了只判断交换、不判断技能就刷新棋盘的问题。现在在回合可行动、全部动画与连锁结束后，按以下顺序处理：

1. 检查当前角色的合法交换，包括骑士整列、精灵斜向及已准备的三线交换。
2. 没有交换时，检查可支付且能产生实际效果的技能。生命代付计入支付能力；满血且无治疗方块的坚守、没有目标的引爆/转生不单独视为有效行动；单纯消除增幅不能解开没有交换的局面。有效治疗等即使不改变棋盘，也可作为行动结束回合。
3. 存在技能行动时保留棋盘。玩家看到“无可交换：可施法 / 点击重排（F2）”，可选择施法或免费重排；重排不消耗回合或资源，可以回滚。血肉施法仍需先预览、再确认，不会为了解局自动扣血。
4. 交换与有效技能均不可用才自动重排。AI没有选择技能又无交换时，可以主动选择重排，不会被迫支付生命。

重排只保证当前角色有合法交换，不改变生命、魔力、增幅或行动方。记录独立的 `board_refresh` 日志；连锁 `resolution` 不再顺带刷新。`fresh_for` 保证刷新后的棋盘无初始三消且当前角色确实有合法交换。

游戏与平衡工具共用 `must_refresh`、`usable_skills` 规则。此修正后的同种子标准AI回归结果保存在 `analysis/deadlock-standard.csv`；前面 `passives-final-*` 是修正前结果，不能混作当前版本的验证数据。

死局修正后的5,040局同种子标准AI回归：骑士50.1%、精灵47.5%、巫师53.1%、哥布林48.8%、小恶魔54.2%、角魔47.9%、大僵尸48.4%；无平局，先手55.1%。真实流程脚本通过99条日志事件验证；另在macOS实际设置无交换但有100魔力的骑士棋盘，确认保留棋盘、F2重排不改资源和回合、undo恢复原棋盘。
