# 素材改为代码绘制的内存调研

2026-10-14。基于当前仓库实际素材、Macroquad 0.4.16 源码与 Release 对照；并未把所有素材改成代码绘制。

## 结论

简单背景值得用几何绘制。角色建议先恢复原始像素分辨率，再按最近邻放大绘制。七种方块和大恶魔带有许多不同颜色/透明度，逐色矩形重绘会显著增加几何与批次，不建议整体替换。

把 PNG 编码为代码数据，再在启动时生成同尺寸 Texture2D，运行时纹理内存基本不变。只有取消纹理、减少纹理尺寸或改变存储格式，才直接减少对应 GPU 像素数据。Macroquad 的 Texture2D 文档明确其内容存于 GPU；RGBA8 输入为每像素4字节。以下原始 RGBA 数量不包含纹理对齐、驱动副本、CPU 解码临时空间和引擎基础内存。

参考：[Texture2D](https://docs.rs/macroquad/0.4.16/macroquad/texture/struct.Texture2D.html)、[draw_rectangle](https://docs.rs/macroquad/0.4.16/macroquad/shapes/fn.draw_rectangle.html)。

## 素材盘点

| 素材 | 原始 RGBA 数据 | 建议 |
| --- | ---: | --- |
| 棋盘背景 1120×1120 | 4.79 MiB | 用简单几何绘制，或提取小块平铺纹理 |
| 单格背景 64×64 | 16 KiB | 代码绘制可行；数据本身很小 |
| 七种方块合计 | 112 KiB | 保留图片，可在构建时组合成一张紧凑图集 |
| 骑士图集 1200×400 | 1.83 MiB | 无损缩小20倍，变成60×20，RGBA仅4800字节 |
| 精灵 / 巫师 / 哥布林 / 角魔 | 各0.46–1.83 MiB | 同样已验证可无损缩小20倍 |
| 大恶魔图集 | 2.12 MiB | 保留图片，后续研究去除插值冗余或更紧凑存储 |
| 死亡“菜”图 | 0.25 MiB | 保留原图，避免改变字形 |

无损缩小验证：将透明像素的隐藏RGB归零后，以最近邻缩小、再还原到原尺寸，逐字节比较RGBA。五张图集完全一致。宽高各缩小20倍，像素数据变为1/400；显示尺寸与动画节奏必须继续使用原始逻辑尺寸，而非缩小后的纹理尺寸。当前只完成验证，没有修改正式素材。

大僵尸、小恶魔的裁剪宽度未对齐放大网格，当前整张图整数缩小未通过；可研究逐帧补齐边界，不能直接判定无法优化。方块图和大恶魔未通过整数缩小校验，不声称简单缩小能逐像素保真。

## 每帧代码绘制的成本

按每行相同RGBA合并水平段，再合并相邻行相同段，得到完全保真的矩形表示：骑士每帧50–57个矩形；大恶魔每帧2969–3461个；单个方块约1080–1466个。棋盘背景整张316个。

64个方块逐色重绘可能需要数万个矩形，而当前只需64个纹理四边形。小批次缓冲不能消除这些顶点、索引、提交及每帧构造的成本。自定义着色器、静态网格或调色板纹理可能改变成本，但此次没有进行这些实现的性能测量。矩形计数只是一种明确的保真实现成本，不是所有代码绘制方式的下界。

棋盘已有 procedural 实验模式，以少量矩形近似重现边框和格子。它保持布局，但未逐像素复刻原图片；此次调研之后已按要求作为正式默认实现，不再加载两张背景纹理；保留原始来源素材用于后续调整。

## 本机实测

同一 Release 二进制，固定窗口、骑士+大恶魔、实际播放BGM、按纹理分组、小缓冲。每个情景两次，第二轮反序；采样5秒和10秒。

| 情景 | 两次10秒 footprint | 两次10秒 RSS |
| --- | --- | --- |
| 原图 | 101.4 / 165.6 MiB | 138.5 / 181.7 MiB |
| 代码绘制棋盘和格子背景 | 98.6 / 94.8 MiB | 132.1 / 131.8 MiB |
| 代码背景并完全移除角色 | 83.4 / 87.9 MiB | 120.7 / 121.5 MiB |

原图第二次明显偏高；vmmap显示图形驻留从23.1增至69.5 MiB，Malloc Large驻留也从约8.4增至20.4 MiB。保留这一结果，不能把两次平均差值全部归因于背景纹理。5秒/10秒CPU采样约10.7–12.1%，样本不足以判断性能差异。

“移除角色”没有绘制任何替代物，作为移除纹理与绘制的对照，不能视为代码角色的实测结果或保证可节省相同内存。内存仍明显高于素材原始像素数据，说明基础窗口、渲染、音频、字体及驱动开销仍占主要部分。

数据见 `analysis/asset-inventory.json`、`analysis/asset-rendering.json`；工具为 `tools/analyze_assets.py`（需要Pillow）、`tools/compare_asset_rendering.py`（macOS）。表中原图对照为切换默认实现之前的数据；当前脚本比较代码背景、移除角色和移除音乐，另存 asset-rendering-current.json，不覆盖历史结果。原始vmmap日志写入忽略的dist/asset-rendering。

建议顺序：五张角色图集无损缩小 → 棋盘几何化或小块平铺 → 七种方块合并紧凑图集。逐项保真验证和实测，避免把全部角色改成大量矩形绘制。
