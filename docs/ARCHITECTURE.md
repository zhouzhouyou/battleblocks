# 代码结构与技能事件

离线平衡评估通过 `src/headless/evaluation.rs` 将种子对任务交给同一个 `Session::headless_batch_match`；`tools/balance/` 只处理已完成对局的采样、版本缓存、统计与报告，不实现战斗规则。详见 [角色平衡评估](BALANCE-EVALUATION.md)。

Headless `Session` 是权威游戏模型，GUI 只是同一模型的输入、帧循环和可视层。战斗规则通过同步、有类型的事件处理器执行；实际战斗、预览和 AI 调用同一套纯规则。通用流程不按角色或技能身份编写特殊分支。

| 位置 | 职责 |
| --- | --- |
| `config/ability-loadouts.txt` | 各角色普通／觉醒的被动、主动身份与觉醒说明；身份配置不是规则实现 |
| `config/role-lore.txt` | 选角尾页的人物档案：称号、介绍、特质与台词，按角色 ID 解析 |
| `src/content/events.rs` | 事件、来源链、处理上下文、注册分发、能力反馈、状态操作请求 |
| `src/content/handlers/` | 主动、被动、临时状态自身的事件过滤与行为；`mod.rs` 只绑定身份和处理器 |
| `src/content/skills/` | 各主动的棋盘操作实现，由施法事件调用 |
| `src/content/rewards.rs` | 构造方块贡献、汇总倍率、分发资源事件、应用上限与终局加压；不识别具体角色或技能 |
| `src/audio/` | 音乐、程序穿门音效与可选系统语音；macOS 后台合成 PCM、共享滤波器和有界缓存，浏览器使用 Web Speech API；不参与战斗规则 |
| `src/content/lore.rs` | 角色档案文本的只读解析与查询，不参与战斗规则 |
| `src/content/status.rs` | 临时效果的身份、施加技能、持续时间及消费规则 |
| `src/content/health.rs`、`movement.rs`、`previews.rs` | 通用生命与觉醒、移动与目标、无副作用预览；能力规则通过事件查询 |
| `src/abilities.rs`、`src/content/definitions.rs` | 稳定能力身份、配置读取和展示元数据 |
| `src/role_state.rs` | 可回滚容器、准备动作和状态列表；通过施法／动作事件更新 |
| `src/app/` | 输入、调用规则、将结果写入状态、执行随机选择与表现反馈 |
| `src/board/topology.rs` | 四向重力图、门边界与成对重连、全局验环、共享棋盘效果生命周期；不含角色规则 |
| `src/board/gravity.rs` | 沿统一重力链压实、随机填充及含穿门路径的移动记录；不含能力规则 |
| `src/debug/` | 命令、完整快照与结构化事件日志 |
| `src/headless.rs` | 无窗口命令行入口、脚本读取、命令队列推进和稳定状态推进 |
| `src/app/headless.rs` | 权威模型的固定步长命令驱动与 idle 判定；不包含另一套战斗规则 |

`src/main.rs` 只负责 GUI／headless 启动分流和窗口配置；输入、战斗结算与界面绘制放在 `src/app/` 下，新增角色逻辑按上表归属。

## Headless 核心与 GUI 可视层

`Session::new_headless()` 构造不加载纹理、字体、音频和窗口的权威游戏模型；`Session::new()` 使用同一 `Session::create()` 路径，只额外加载 GUI 资源。公共战斗、调试命令、快照、AI、表现计时和事件结算全部由同一个 `Session` 驱动。

- GUI 每帧调用输入适配、`tick` 和 `draw`。
- Headless 每帧用固定步长调用同一 `tick`；调试命令通过同一 `debug::Console` 队列和 `process_console_command` 执行。
- `--headless` 不会进入 Macroquad 窗口事件循环；`--script`、`--command` 提供操作序列，结果以 JSONL 和最终摘要输出。
- 默认 headless 静默逐条事件 stdout，只输出命令反馈与 `HEADLESS_OK`；`--verbose` 恢复逐事件文本。JSONL 始终完整。
- 行棋、施法、AI、回合结束、觉醒、待结算消除和回滚都通过同一条模型路径，不得在 CLI 适配层复制规则。
- 批量模拟统一使用 `--headless --autoplay` 或平衡评估入口；`src/bin/` 不再维护独立的对局模拟器。

普通、整列和准备交换的棋盘操作共用 `board::exchange_in`；普通与强制交换的移动几何共用 `board::swap_shape_in`。角色状态消费、费用和表现仍由各自调用层负责。AI 对候选后续移动的评分使用 `strategy::best_move_score_in`，不另写收益结算。

## 界面绘制

提示输入与绘制共用 `src/app/hints.rs` 的只读排名缓存。普通 H 提示比较单次交换；Shift + H 切换组合提示，Esc 关闭。AI 与组合提示共用 `src/app/planning.rs` 的候选生成、推演和排序入口，但使用不同搜索策略。三档 AI 以推演深度区分：入门不推演（随机合法交换）；标准只推演一步（`depth = 1`，按实际结算比较交换与技能）；进阶推演至多八步，并对即时排名前六的方案追加「对手最佳回合 → 己方后续回合」重评分（`reply`／`follow_up`），用对抗结果而不是仅看即时收益排序。组合提示保持独立的六步深度与十二分支上限，展示排名前六的完整方案；这是有界候选搜索，不保证穷尽所有目标组合。候选在独立的 headless `Session` 中按实际规则推演施法、准备移动、交换和补充连锁，共用 `strategy::reward_value` 的资源权重。费用、冷却、连续施法加价、状态、血量与魔力上限均通过实际动作和结算路径计算；回合交接由 `finish_turn` 复用真实回合开始／结束规则。

设置菜单的「实验」页只改变 AI 的推演范围与排序，不改变规则：可分别关闭对手技能、对手反击、后续回合与传送门／重力技能。`strategy::AiExperiment` 进入搜索策略缓存键，切换后立即重算；关闭反击时后续回合不参与评估，关闭传送门时 AI 不主动选择布门或重力改向技能，但场上已有门的物理结算仍按正常规则执行。

组合预览缓存包含完整规则快照与随机流状态（忽略表现计时），普通提示键包含棋盘、双方资源、角色、准备状态和完整 `Rules`；状态变化重新计算，回滚显式清空。推演使用不创建日志、不读取命令或 stdin 的独立控制台，结束后恢复实时随机流，缓存不属于战斗快照。点击组合方案后，输入队列等待每一步动画和结算完成，再核对规则快照并通过正常输入路径执行下一步；局面改变、手动操作、Esc、回滚或重开会中止队列。组合面板按步骤数计算卡片与外框高度，分页、绘制和点击使用相同几何，文字按可用宽度收敛字号。特效图集的帧坐标和裁剪共用 `src/effects/atlas.rs`，各特效保留独立事件时钟和动作时序。

- 矩形描边统一用 `graphics::outline`：它把四条边画成对齐设备像素的实心矩形，任意窗口缩放下四边都可见，最小也是 1 个设备像素。不要再直接调用 `draw_rectangle_lines`：它在矩形内侧只描一半厚度，1 像素的边会正好落在两个像素中心之间而整条消失（右侧最常见），窗口缩放为小数时尤其明显。
- 面板的框、内边距和页签几何来自 `ui::PANEL` 与 `ui::help_tab_rect`：绘制和点击热区共用同一份几何，页签按内容宽度均分，任何页签都不会超出面板内边距。新增面板内容同样从 `PANEL_LEFT`／`PANEL_INNER` 取宽度，并用 `fit_size` 收敛文案，避免内容压到边框。

## 事件与执行次序

节点包括方块贡献、消除倍率、消除汇总、资源事件、目标接收、施法、技能效果、费用、魔力上限、操作范围、移动方式、目标合法性、回合结束、对手回合结束、能力刷新、临时效果完成及外观查询。注册的能力接收事件并自行筛选；通用流程不判断能力名称。主动效果、AI 对特定主动的评价和目标方式也由主动处理器提供。

消除先为每个方块建立治疗、伤害与魔力事件。来源记录当时位置、方块类型、连锁波次和是否为交换引发。来源侧的方块加成与汇总倍率由能力处理器修改。整数倍率仍对总数取整，再按累计比例分配回各来源，保留总值和来源位置。

资源事件按确定顺序进入队列，分发给当前生效的能力。处理器可以保留原事件、取消原事件或创建子事件。子事件重新进入队列，所有相关能力均可处理它；每份子事件复制父来源链，并追加本次实际产生效果的能力。处理器使用来源链避免重复处理同一路径，队列另有异常循环上限。角色配置中的监听顺序与状态插入顺序确定执行次序。

未取消的事件进入目标接收阶段，由目标技能过滤，再汇总和应用生命／魔力上限。伤害最终通过统一生命／觉醒入口落地，维持一次结算不穿透觉醒第二生命条的现有规则。生命上限截断不能提前消掉治疗触发。

## 当前来源和来源链

`RewardEvent.current_source()` 返回最近来源。`causes` 保存根到当前的完整链，并记录每一步的释放方。例如：

- 普通修女：方块消除的自身治疗→友谊之奶的对手治疗。
- 临时癫狂：方块消除→友谊之奶→癫狂状态的对手伤害。
- 觉醒修女：友谊之奶仍生效；原自身治疗和派生对手治疗分别由癫狂被动转为伤害。
- 回归理性：状态通过能力启用查询暂时禁用癫狂，普通攻击不转换。

矮被动只过滤最近来源为重力上游交换消除方块的伤害（上游按当前下沉方向计算）。转换后最近来源是修女能力或状态，原方块位置仅供追溯，不再触发矮。调试 JSONL 的 `reward_event.payload` 保存资源、接收方、数值、当前来源及完整 `source_chain`。

## 状态、反馈与回滚

临时状态保存在 RoleState 和 Rules 的状态列表中，包含施加技能和持续期：己方回合结束计数、下次交换、下次消除。全部进入快照和 JSONL；跨回合准备状态保留到消费，回合效果在真正的回合边界过期。跳跃、癫狂、理性、消除增幅及三线准备均使用该列表，界面有独立状态栏。强制移动的 `force_armed` 直接保存在 RoleState 中。连续施法计数 `repeat_casts` 与完整回合数 `round` 也属于快照状态：前者在回合开始清空，后者驱动终局加压。

能力处理器返回 `AbilityTrigger`。规则计算只生成反馈数据；Session 在实战中记录触发日志并显示所属角色的反馈。矮触发时显示「你打不到我！」，同一波同一能力的反馈去重。预览与 AI 保留同一触发结果但不播放反馈。撤销恢复规则状态，并清除临时表现。

技能需要随机选择时返回状态操作请求，由 Session 使用可回滚的随机流执行，例如心灵视界和复制；预览不抽取随机数。

## 扩展与验证

新增技能应注册处理器、配置身份和参数，在处理器内接收事件／检查来源／生成结果或子事件。通用结算、输入、预览或 AI 中出现具体角色／技能身份判断，意味着规则尚未迁入处理器。素材身份、图标和动画注册属于表现配置。

改动收益或事件顺序时验证实际规则、费用、上限、目标差异、来源链、事件终止、预览纯度及回滚。检查选择与构建交付统一遵循 [构建与验证](BUILDING.md#验证选择)。

传送门与重力接入见 [PORTAL-MECHANICS.md](PORTAL-MECHANICS.md)。`BoardMechanics` 是共享棋盘状态，含施法者与下次自己回合开始过期语义，进入 Snapshot／JSONL；角色被动只监听 `PortalTransit`，不搬运方块。重力方向、深度、门边、默认配对与插入推移都由 `src/board/` 提供；技能只表达目标与效果，不自行按重力分支。

## 资源与输出的边界

当前游戏使用无损 WebP 保留像素与透明度，使用简单几何绘制棋盘背景；不把复杂角色纹理逐像素改为绘图指令。原生音频使用压缩音乐和有界播放缓冲，包内编码大小与运行时内存分别评估。保留可复用实验与复现方法，单次测量数字和日志不随源码保存。资源和输入目录遵从 [LAYOUT.md](LAYOUT.md)。

运行纹理通过 `graphics::decode_webp` 显式调用 WebP 解码器，再上传 RGBA；不使用通用图片格式检测，避免把未使用的 PNG 解码路径带入发布包。字体仍由独立字体加载入口处理。

纹理按界面阶段加载，不按“全部资源”一次载入。`graphics::Sheet` 在第一次 `get` 时才解码并上传；`Session` 在选角界面只加载当前英雄，对手与觉醒图集属于战斗资源，进入战斗时才加载。技能特效表只做空表，开战时按双方普通／觉醒可用技能预取（复制或调试命令带来的其他技能在首次使用时解码）；返回选角时释放战斗专用贴图。新增战斗贴图遵循同一路径，不得在 `Session::create` 中直接解码。

`src/assets.rs` 的 `asset!` 是全部运行时美术的唯一注册方式：本地构建用 `include_bytes!` 内嵌，Web 构建把它们放在 `.wasm` 外的 `dist/web/assets/`。Web 端 `Session` 第一次需要某张图集或特效表时排队请求，帧循环用 miniquad 的回调式 `load_file` 在后台拉取，完成后 `refresh_textures` 补建纹理；等待期间界面照常绘制，缺失的角色在选角与战斗中用缩略图加召唤环占位，不覆盖全屏加载页。首页只需当前英雄一张图集，其余资源随选人和开战按需下载，可见名单会在后台预热。新增资源必须走 `asset!`，打包脚本按同一清单复制文件。

战斗画布为 1184×720，默认窗口 1480×900。棋盘及居中菜单继续共享原有中心，左右角色栏通过 `graphics::sidebar_x` 各向外移动 80 逻辑像素，为弹弓留出独立操作区；卡片、口袋、提示和角色特效的绘制与命中使用同一坐标变换。相机及像素对齐比例读取 `ui::CANVAS`，全屏遮罩覆盖扩展后的画布。

## 弹射能力

弹弓手为独立新角色（ID 13），列入新角色页，技能槽为轻型、重型弹弓；普通与觉醒使用独立持弓动画，缩略图复用自身图集首帧。老哥布林（ID 3）继续使用原有魔力换血、区域掠夺和被动。主动处理器 `handlers/slingshot.rs` 通过 `SkillProfile.projectile` 提供参数，通用输入、绘制和提交只读取能力配置。`config/projectiles.txt` 按技能和觉醒状态维护速度、角度、重力、弹珠半径、各资源的收益百分比及概率、爆炸半径、弹丸质量比与引爆条件。轻型配置禁止爆炸，重型觉醒解锁弹丸选择；有类型的 `Aim.ammo` 决定实心弹或爆弹。爆弹按质量降低初速，飞行 0.8 秒或提前落地时自动结束飞行并爆炸；觉醒「滑轮增压」只提高初速，保持方块收益比例。普通形态不设被动。`Rules.launch_from_right` 决定物理发射方向；快照中的 `perspective_reversed` 跟随 AI 视角交换，避免敌方推演与实际命中不一致。

`content/projectile.rs` 使用棋盘格为单位、f64 解析抛体运动，固定发射点为棋盘左侧 `(-0.3, 7.2)`，敌方镜像到右侧。加速度方向读取当前棋盘重力，发射点与瞄准角度保持屏幕坐标。水平镜像求解时同步镜像加速度，输出轨迹恢复实际重力方向。连续圆与矩形碰撞由边界方程和四次角点方程求根，按导数根分区、固定次数二分求解，命中误差与渲染帧率无关。同一时刻采用 1 ns 比较容差，先完整处理接触批次，再判穿透引爆、引信和落地。沿当前重力方向接触下游棋盘边界视为落地。水平方向完全出界终止，发射侧保留弹弓操作区，允许逆向重力使弹丸折返。未接触下游边界时允许飞出棋盘上方。爆炸按圆与方块矩形相交，穿透来源优先，重叠格不重复结算。

弹射收益使用独立的 `EventSource::Projectile`，包含技能、格子、方块与爆炸标记。它经过已有资源事件、目标被动、上限和觉醒结算。普通三消的方块倍率、清除汇总被动与「下次三消」状态不响应直接弹射，后续下落连锁正常响应各施法者自身的三消被动。各资源独立按配置概率判定；同源资源百分比先汇总取整，再分配到格子。成功与未触发事件通过正式事件的正数／零数值区分，飞行日志保存命中时间、顺序、物理位置及引爆原因。

发射确认后重新求解，费用立即支付，完整飞行和待提交资源批次保存在可回滚的 `PendingImpact`。表现计时锁定棋盘，结束后提交资源，再处理下落与连锁。快照恢复飞行剩余时间，跳过或改变帧长不改变结果。界面曲线与弹珠使用同一解析位置，独立显示穿透、爆炸额外格与去重总数。

预览显示初次收益和费用后的净魔力。存在概率时标为近似值，普通预览按各事件的期望金额计算，其截断和非线性被动可能产生近似误差。含补充连锁的期望由十二个独立固定随机流在隔离 `Session` 中按完整动作路径采样，并明确标注近似。采样覆盖被动、目标、上限和连锁，不读取或推进正式随机流；预览缓存键包含规则快照、技能和量化瞄准输入。AI 和组合提示使用 `PlanAction::Shoot` 携带完整瞄准输入，通过相同技能路径分别评估可用弹丸的 8×8 角度／力度候选。
