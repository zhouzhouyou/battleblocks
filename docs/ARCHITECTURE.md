# 代码结构与角色扩展

本次重构保留现有玩法。`main.rs` 只建立窗口、初始化字体、创建 Session 并逐帧调用。Session 是原来入口函数持有的运行状态；Frame 只保存当帧输入和视口，不保存战斗规则。没有新增角色基类、插件注册系统、事件总线或技能脚本语言。

## 职责

| 位置 | 职责 |
| --- | --- |
| `src/app/mod.rs` | 会话状态、只读规则上下文、快照与恢复、伤害／觉醒入口 |
| `src/app/lifecycle.rs` | 选角开战与重开共用的初始化 |
| `src/app/controls.rs`、`console.rs`、`selection.rs` | 全局操作、调试命令、角色和对手选择 |
| `src/app/combat.rs`、`turn.rs` | 战斗帧执行顺序、回合切换与冷却推进 |
| `src/app/actions.rs`、`exchange.rs`、`resolution.rs` | 技能操作与 AI 决策调用、交换、消除和连锁 |
| `src/app/view/` | HUD、棋盘、提示、技能卡与说明、覆盖层；按显示职责拆分 |
| `src/content/definitions.rs` | 角色／技能配置、技能列表、冷却元数据、复制技能解析 |
| `src/content/skills/` | 新骑士、矮人、牧师的实际技能效果；legacy.rs 保存逐步替换的旧技能 |
| `src/content/rewards.rs` | 方块收益、被动修正、资源结算与费用支付 |
| `src/content/health.rs`、`movement.rs`、`previews.rs` | 生命与觉醒、可操作范围与目标、无副作用的收益预览 |
| `src/role_state.rs` | 口袋、跳跃、强制移动、直接消除记录等可回滚状态 |
| `src/board/gravity.rs` | 方块压实、随机填充与移动起终点；不包含复生的插入规则 |
| `src/graphics.rs`、`presentation.rs` | 字体与通用绘制工具、动画表现 |
| `src/debug/` | 命令解析、快照序列化、调试测试；debug.rs 保留控制台与日志 |

content.rs 是供实战、AI、预览和历史平衡工具共用的稳定入口，不放实现与长测试。测试移至独立文件，仍覆盖原来的公开规则。旧平衡工具只模拟旧七角色，其范围没有因重构扩大。

## 增加到十四位角色时

先更新已确定的角色和技能配置及素材；新增实际效果放进对应角色技能文件，在 effects.rs 明确分发。可组合现有效果时直接复用普通函数，不为了角色数量创建十四个对象或十四套相同流程。冷却数组长度来自 Skill::ALL，不另写技能总数。普通／觉醒被动仍由现有身份表管理。

只在需要跨行动保留数据时扩展 RoleState 或会话状态，并同步 Snapshot、恢复和 JSONL 序列化。`new_role_states` 是现有日志中的兼容字段名，仍保留。临时界面目标和动画不成为额外的规则来源。新增规则需同时验证玩家、AI、预览与回滚。

## 已知的后续技能如何落地

「本回合所有治疗改为对敌人造成伤害」：实战直接技能和消除都先调用 app 的 apply_rewards，并与技能／交换预览共用 content::settle_rewards。以后在这个纯结算点加入回合转换，先转换再处理生命上限，避免只转换方块治疗而漏掉主动技能，或把溢出治疗提前截掉。转换状态应进入 RoleState、Rules、快照，并在真正的回合边界重置；预览只读取它。当前没有增加该技能或一个尚未使用的转换标志。

「修改本回合重力方向」：填充算法集中于 board/gravity.rs，移动记录已使用二维起终点，表现层按记录播放，不再假定只有纵坐标变化。当前仍仅执行向下重力；新增方向时在该模块统一处理压实顺序、边界补充及随机数顺序，并让回合方向进入快照。复生向下插入是独立的既定技能规则，不能因改变重力而顺带修改。

## 验证

使用原有 Rust 测试、check_debug_console.py 和 check_new_roles.py 验证费用、资源上限、目标差异、预览不改状态、随机流和完整回滚；增加二维掉落动画测试。使用 tools/build.py 更新 macOS 与 Web 包，再检查实际画面。
