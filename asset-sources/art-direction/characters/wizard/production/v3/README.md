用户最终明确：普通版保持不变、保持粗像素；觉醒版保持细像素，本Issue只优化觉醒相关动画。已先更新#11、#27、#28、#29范围，再改本实现。

**普通完全不由本导入器处理。** 普通运行时仍读取原 `assets/wizzard.webp`，300×400帧、索引0/1/2/3、每帧0.1秒、无新增施法clip、无新脚锚，原缩略图恢复。`tools/check_wizard_normal_unchanged.py` 相对500673e验证普通素材与缩略图字节、普通注册表与元数据未变。

本目录只包含觉醒待机和觉醒施法，各12张独立姿势。两份 `*-source-v3.webp` 是v1已有细像素觉醒源图的逐字节复制，没有重新生成或重新设计角色。两份 `*-original-prompt.md` 原样记录当时内置imagegen提示词；只继承觉醒源图，提示词中涉及普通形态统一的历史描述不再作为需求。原始角色参考仍是 `assets/awakened/wizard-awakening.webp`。

导出保持细像素簇、64共享色、二值alpha、无抖动、最近邻，帧384×384、鞋底锚点(192,336)。源格362×362，同一缩放与逐帧鞋底注册用于两个动作；不使用v2的24×24粗像素网格。图集2304×1536（6×4），0–11觉醒待机，12–23觉醒施法，共24帧。`report.json`记录每帧像素哈希与边界；该24帧与v1中的对应觉醒帧像素相同，普通帧没有被带入。

待机12×60ms；施法ms为60,80,90,90,120,180,280,100,100,100,100,100。第5帧出手、第7帧引导、第8帧命中，命中后0.5s收势。只有觉醒施法采用真实命中时钟；普通原有表现保持。导入使用仓库Python运行 `tools/prepare_character_animations.py --role wizard`，再 `--registry-only`；完整 `tools/prepare_assets.py` 也包含该入口。动画WebP为循环评审文件，运行时施法Once。
