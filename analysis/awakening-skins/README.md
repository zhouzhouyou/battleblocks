# 觉醒皮肤审阅资源

状态：七角色单帧皮肤已接入游戏；觉醒演出由代码实现，不包含独立的多帧待机/攻击图集。

- 保留原来的主配色、头脸与标志特征，中等幅度增加像素层次。
- 觉醒后持有对应武器；骑士青绿甲胄不改色。
- 精灵为女性，金色长发、绿色服装，持短弓。
- 哥布林不穿铠甲：布衣、腰带、裸露绿色手臂，持匕首。
- 由内置 imagegen 生成，依据原角色图集与已确认的骑士细节程度；未使用 API/CLI 回退。

## 文件与压缩

七张精灵均以实际内容边界去除透明留白，再按最近邻采样到 96 像素高；这是候选游戏尺寸，不是最终美术源图。原始生成图保留在 manifest.json 的 source 路径中。

| 哥布林 | 匕首 | goblin-awakening.png | goblin-awakening.webp |
| 小恶魔 | 三叉戟 | imp-awakening.png | imp-awakening.webp |
| 角魔 | 战斧 | chort-awakening.png | chort-awakening.webp |
| 大僵尸 | 石锤 | zombie-awakening.png | zombie-awakening.webp |

PNG 合计 60,529 字节（59.1 KiB）；无损 WebP 合计 50,102 字节（48.9 KiB）。相同尺寸的两种格式解码后 RGBA 像素逐字节一致，包括透明度。压缩后尺寸、源路径和逐图体积见 manifest.json。

当前 Macroquad 0.4.16 依赖的 image 0.24.9 只启用 png/tga，游戏的 texture() 也明确指定 PNG。直接将扩展名改为 WebP 无法加载。image 0.24.9 的 webp 功能本身未声明新 crate 依赖，但仍需要显式启用这个功能，并调整格式加载逻辑；解码代码会增加二进制，不能只按素材节省约 10 KiB 来判断总包体收益。

当前保留 PNG 候选可以直接沿用已有解码能力，完全不用修改 Rust 依赖；WebP 用于浏览器审阅与后续包体比较。本轮未改变 Cargo.toml、Cargo.lock；七张 PNG 已复制至 assets/awakened/ 并随 macOS / Web 构建包交付。

## 最终提示词组

共同约束：以原图集第一帧保持身份，以已确认骑士为中等细节参考；约 32×40 至 40×48 原生像素观感；保留原主色、物种、脸、发型、角与胡须；适度增加衣褶、甲片或材质层次；右向三分之四全身；武器可见且握在手中；透明背景；不要新冠冕、翅膀、华丽新服装、大光环、细碎纹饰与平滑渲染。

## UI 审阅范围

审阅稿包含皮肤对比、角色与对手说明分页、战斗前后状态、悬浮血条提示、可重播觉醒动效、技能预估、现有方块说明入口的觉醒页签、原有暂停与简洁胜负页。魔力上限 +100、魔力 +60 只用于展示变化动效，不表示已新增角色规则。角色觉醒血线与强化仍是此前讨论的待验证原型参数。

最终规则已更新：生命代付可触发觉醒；骑士觉醒后坚守回复消耗80魔力、回复新生命上限20%；战斗中不显示“已觉醒”徽标。以 docs/AWAKENING.md 为当前规则，历史审阅稿中的旧说明不再适用。
