# 字体与资源生命周期审查

2026-10-14，macOS Apple Silicon；所有比较使用 Release。此前基础对照见 REPORT.md。

## 确认的问题与修复

1. 窗口缩放通过 camera_font_scale 产生不断变化的字体栅格字号。Macroquad 按字符和字号缓存，没有自动淘汰。现限制为 16、24、32、48、64 五档，通过绘制缩放保持视觉尺寸。DPI 会影响实际栅格尺寸，五档限制针对固定 DPI。
2. 一帧中边画文字边添加字形，可能扩张字体图集并替换 GPU 纹理，而此前批次已引用旧纹理。现先收集整帧文本，填充所有字形，再统一绘制。压力实验验证这一时序修改解决了异常的大额图形内存分配；具体驱动内部行为仍未唯一定位。
3. 点击已选角色仍会解码并上传其图集。现跳过同一角色重复加载。

文本队列及字符串复用存储，避免新增逐帧队列分配。图集纹理 Drop 有释放路径；未发现角色纹理被长期强引用的证据。批处理中的弱引用元数据仍可能随真实角色切换累积，不能据此宣称所有长期增长均已排除。

## 字体压力实验

无音频独立程序，512 顶点 / 768 索引小缓冲，6 行文字，15 秒，两次运行。快速变字号是合成压力情景，不代表普通游戏会达到这些数值。

| 情景 | 15 秒 footprint |
| --- | --- |
| 固定字号 | 66.8 / 67.0 MiB |
| 每帧变化、65 个字号 | 一次有效结果 2252.8 MiB |
| 限制五档、边绘制边缓存 | 804.6 / 804.4 MiB |
| 限制五档、整帧预缓存 | 67.0 / 66.5 MiB |

65 字号第二次出现约 45 GiB footprint、5.64 MiB RSS 的矛盾异常计数，排除比较，保留原始记录。没有将其解释为实际占用 45 GiB RAM。数据见 data/font-cache-audit.json；重现命令为 python3 run.py --font-cache 和 --font-frame。无界压力情景可能导致大量图形分配，不建议日常重复运行。

## 实际游戏与验证

完整游戏、原始棋盘图片、骑士和大恶魔、BGM 实际播放：5 / 15 / 30 秒 RSS 为 137.4 / 137.3 / 133.3 MiB，footprint 为 100.2 / 100.0 / 92.5 MiB。见 data/game-font-fix.json。该短测没有持续增长，但不证明长期无泄漏；相比此前约 94–99 MiB 的普通游戏测量，差异处于运行波动范围。字体修复主要避免窗口缩放和新字形出现时的异常，不宣称正常场景节省数百 MiB。

11 项测试通过，原生及 WASM Release 构建通过。浏览器检查中文、英文及暂停遮罩文字均正常；截图见 data/font-fix-preview.png。

Mac 统一内存和 RSS 统计口径确实影响基础数值，但无法解释或豁免上述可复现的绘制问题。当前修复及独立实验尚未提交 Git。
