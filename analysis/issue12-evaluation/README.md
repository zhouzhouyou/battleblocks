# Issue #12 验收证据（2026-11-03）

范围：新五人（7、8、9、10、11），标准 AI，正常随机开局，双方先手各一次。预算指完整对局数；一个独立种子对含两局。数据通过同一个 `Session::headless_batch_match` 产生。

## 独立参考集结果

训练池 1,280 局（根种子 121001），最终参考集 2,560 局（125001），双方种子不重叠。算法与比较口径在查看最终参考结果前冻结。每个预算做 12 次固定训练池重排，两个采样策略使用相同池与同一估计器。下表 RMSE 是配对得分率的误差，越低越好；全部数据无平局，因此本次得分率等于胜率。

| 总预算 | 原均匀＋原始胜率 | 均匀＋新估计器 | 自适应＋新估计器 | 相对原系统误差下降 |
|---:|---:|---:|---:|---:|
| 100 | 0.14358 | 0.11904 | 0.11574 | 19.4% |
| 200 | 0.10612 | 0.09300 | 0.09463 | 10.8% |
| 400 | 0.07861 | 0.07110 | 0.07120 | 9.4% |
| 800 | 0.05992 | 0.05343 | 0.05325 | 11.1% |

结论限于上述阵容、固定 AI、训练池和预算：新系统端到端的平均误差低于原有均匀采样原始胜率。**收益主要来自收缩估计，自适应采样单独没有稳定优势**，200/400 局时同估计器的均匀分配略好。没有宣称所有阵容或预算都成立，也没有将 12 次重排当作独立实验重复或作统计显著性声明。

完整指标见 `benchmark.json`，包括 Brier、排名 Spearman、候选极端关系精确率/召回率、区间覆盖参考均值比例与循环。800 局时两策略平均排名相关性均为 0.633；候选极端关系平均召回率均匀为 75.0%、自适应为 83.3%。本批预算内严格置信序列确认的极端关系数都是 0，不能把候选检测称为统计确认。参考胜率也有有限样本误差。

## 数据、版本与复现

- `training/`：训练原始对局、manifest 与报告。
- `reference/`：最终独立参考对局、manifest 与报告。
- `development-reference/`：先前开发参考集，2,560 局，根种子 122001；不作为最终独立验证。
- `development-initial.json`、`development-revised.json`：开发阶段比较。初始静态残差采样权重没有稳定优势；改用配对方差与边际误差下降近似后，再采集新的最终参考集。两份开发结果均保留，避免只展示有利预算。
- `final-build-replay.json`：最终输入修复版本对 100 局原始结果的逐字段一致性复核；全部十个配对，每组取训练前两个种子对及最终参考前三个种子对。
- `all-smoke.json`：全部 12 角色、24 局稀疏采样，全部角色均参与；`advanced-smoke.json`：进阶 AI 的 40 局兼容冒烟。两者不用于宣称预测精度优势。
- `SHA256SUMS.json`：原始 gzip 对局和报告的校验和。JSONL 压缩设置 mtime=0。

采集程序源码对应提交 **6ef194335f276d6ad458089093b8896ab398ecf1**，该 Windows release 程序 SHA-256 为 `a44ffe6cf1757fd8024eb3821d32d7dfe51b040066a7429fbbf90925e35fe5a9`。全部原始 manifest 保留其实际共享指纹。

最终参考集采集到 1,808 局时，旧构建触发控制台与评估接口竞争 stdin 的传输错误。校验拒绝缺失输出，未写入损坏记录；一次普通恢复也失败。随后仍用冻结采集程序补齐相同预定种子序列。补采脚本允许仅在缺失输出时重试同一任务（最多 20 次，不更换种子、不筛选结果），该次成功补采实际重试数为 0，新增 752 局。训练首次采集约 310.5 秒；开发参考约 588.9 秒；最终参考中断前约 327.8 秒、成功补采约 86.8 秒；并发和编译负载不同，这些数值不构成速度对照。

最终代码修复仅使 `--evaluate-jobs` 独占 stdin 并跳过空调试日志；未修改游戏规则。最终程序的共享指纹因此改变，**没有把旧数据改写成新版本，也没有绕过缓存失效**。以独立的 100 局同种子逐字段回放证明输入修复未改变这些样本的结果；具体新指纹与程序哈希见 `final-build-replay.json`。后续在最终程序运行评估时，正常使用它自己的新缓存键。

离线复现比较，无需重新模拟：

```sh
python tools/benchmark_balance.py \
  --training analysis/issue12-evaluation/training \
  --reference analysis/issue12-evaluation/reference \
  --budgets 100,200,400,800 --repetitions 12 \
  --out analysis/evaluation-runs/replayed-benchmark.json
```

`python` 使用 `.build-tools/python-path.txt` 的解释器。重新采集时使用 [评估文档](../../docs/BALANCE-EVALUATION.md) 的命令，并将最终参考根种子设为 125001；编译版本不同会生成独立缓存。
